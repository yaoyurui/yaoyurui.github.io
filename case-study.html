不自动改标签

我明确约束了什么

  • 模型不计算版本统计，也不修改原始标签。
  • 信息不足时提示补充，没有匹配依据时不生成规则结论。
  • 规则冲突交由人工核对，不让模型代选最终标准。
  • 模型失败时保留检索条款，允许继续人工复核。

技术范围

小规模资料，先把依据做清楚。

当前使用关键词检索，未引入向量数据库。来源信息包括文档、条款、产品、版本和位置；无法获取的页码标记为“未提供”。

本地栈为 Python 标准库、SQLite 与 HTML / JavaScript。模型密钥留在后端；可用 Windows 当前用户加密方式记住。

  • 按样本编号匹配，区分已修复、新增错误及持续错误。

  • 真实模型调用成功，并保留生成结果与查询快照。
仍需验证

实际使用是否足够好用

  • 尚未完成真实测试人员的独立任务试用。
  • 尚无人工整理与工具辅助的耗时对照数据。
  • 尚未验证真实企业标准与产线资料的适用性。
  • 免费模型繁忙时的体验仍有改善空间。

一次有价值的失败

同样是请求失败，处理建议应该不同。

接入过程中遇到 401 鉴权失败和 429 限制。进一步识别业务码后，确认其中一次 429 为 1305：模型当前访问量过大。因此把笼统提示改为脱敏的具体原因，保留本地条款；请求失败时不自动切换付费模型。
